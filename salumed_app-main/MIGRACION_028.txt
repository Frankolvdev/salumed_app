MegaZIP 028 — Alineación JVM automática para todos los plugins

Base exacta:
- salumed_app-main (7).zip

Problema:
La configuración anterior mantenía una lista manual:

- algunos plugins en JVM 1.8
- otros en JVM 11
- otros en JVM 17

Cada compilación avanzaba hasta el siguiente plugin y aparecía otra
incompatibilidad entre compileDebugJavaWithJavac y compileDebugKotlin.

Corrección definitiva:
Se elimina la lista manual por nombres de plugins.

Para cada tarea Kotlin, la configuración busca su tarea Java equivalente:

compileDebugKotlin
    -> compileDebugJavaWithJavac

compileReleaseKotlin
    -> compileReleaseJavaWithJavac

y configura Kotlin con el target real de Java:

Java 1.8 -> Kotlin JVM 1.8
Java 11  -> Kotlin JVM 11
Java 17  -> Kotlin JVM 17
Java 21  -> Kotlin JVM 21

Esto cubre automáticamente:
- google_maps_flutter_android
- firebase_core
- firebase_messaging
- image_picker_android
- geolocator_android
- permission_handler_android
- url_launcher_android
- video_player_android
- webview_flutter_android
- shared_preferences_android
- sqflite_android
- package_info_plus
- onesignal_flutter
- just_audio
- y los demás módulos Kotlin Android presentes o futuros.

No se modifica:
- ningún archivo del Pub Cache
- código fuente de plugins externos
- código Dart
- diseño
- pagos
- applicationId
- compileSdk
- targetSdk
- funcionalidad de audio
- funcionalidad web

Aplicación:
1. Descomprimir encima de:
   F:\SALUMED\CODE\APP

2. Limpiar completamente:

cd .\android
.\gradlew.bat --stop
cd ..

flutter clean
Remove-Item -Recurse -Force .\build -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\.dart_tool -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\android\.gradle -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "$env:USERPROFILE\.gradle\caches\9.1.0" -ErrorAction SilentlyContinue

flutter pub get
flutter build apk --debug -v *> build_028.log
