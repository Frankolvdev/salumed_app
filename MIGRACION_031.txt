MegaZIP 031 — JVM automática mediante Provider estable

Base exacta:
- salumed_app-main (9).zip

Problema anterior:
La regla automática anidaba configureEach de JavaCompile dentro de la creación
de una tarea KotlinCompile. Gradle 9 lo rechazaba con IllegalMutationException:

DefaultTaskCollection#configureEach(Action) cannot be executed in the current context.

Corrección:
- Se elimina la configuración anidada de colecciones de tareas.
- Se elimina cualquier dependencia de afterEvaluate.
- Cada tarea Kotlin crea un Provider<JvmTarget>.
- El Provider consulta la tarea Java equivalente cuando Gradle necesita el valor.
- Kotlin adopta el targetCompatibility real de Java.

Mapeo:
- Java 1.8 -> Kotlin JVM 1.8
- Java 11  -> Kotlin JVM 11
- Java 17  -> Kotlin JVM 17
- Java 21  -> Kotlin JVM 21

Si una tarea Kotlin no tiene tarea Java equivalente, usa JVM 17 como valor
seguro para el entorno Android actual.

No modifica:
- código Dart
- código fuente de plugins externos
- Pub Cache
- diseño
- pagos
- applicationId
- compileSdk
- targetSdk
- recursos Android

Aplicación:
1. Descomprimir encima de:
   F:\SALUMED\CODE\APP

2. Limpiar completamente:

cd .\android
.\gradlew.bat --stop
cd ..

flutter clean
Remove-Item -Recurse -Force .\build -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\.dart_tool -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\android\.gradle -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "$env:USERPROFILE\.gradle\caches\9.1.0" -ErrorAction SilentlyContinue

flutter pub get
flutter build apk --debug -v *> build_031.log
